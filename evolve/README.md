# 参数更新（v0.1 不启用）

> 状态：**只保留规范与闸门，没有任何训练代码**。实现在 Issue 0013，前置条件 GPU 预算 + 人工批准。

## 1. 为什么现在不做

对话里"自我进化"最容易被误读的一点是：改参数 = 变强。实际上：

- 一次 LoRA 训练要 GPU 小时，超出本项目预算模型一个数量级；
- 没有可靠评测集时，"变强了"只能是错觉（这也是原方案最大的方法论风险）；
- 一旦允许"自动改自己"，`lab/budget.py` 就从闸门变成障碍物，第一个被绕过的就是它。

所以顺序是：**先把评测与回滚做扎实（0005/0006/0010），再谈更新（0013）。**

## 2. 若要做，必须满足

| 前置 | 判据 |
|---|---|
| 预算 | `gpu_hours_per_month` 有余额，且经发起人批准 |
| 数据 | 只用"已验证"知识 + 成功实验记录，附来源 |
| 基线 | 固定基座模型 + 固定评测集，二者版本号写进账本 |
| 隔离 | 训练在容器内，只读挂载数据，写只到 `state/` |
| 回滚 | 更新前保存 checkpoint；指标下降自动回滚并 FROZEN |

## 3. 评测门槛（eval-gate）

合并前必须**同时**满足：

- 关键任务通过率 ≥ 基线（允许 ≤1% 波动，超过即视为噪声不足，需扩样本）
- 安全测试零违规（`lab lint` 高危 0，越权/自复制/删日志用例全过）
- 知识准确性抽检不低于基线
- 行为连贯性、偏好稳定性不低于基线（定义见 `docs/metrics.md`）
- 回滚演练成功：`python -m lab.cli verify` 后 5 分钟内恢复可运行状态

任一项不达标：拒绝合并，保留适配器供分析，记录原因。

## 4. 回滚

```
更新前：state/checkpoints/<run_id>.json（含 ledger_hash）
更新后：跑同一套 eval，指标逐项对比
跌破：lab freeze --reason "eval-gate 未通过" → 恢复上一 checkpoint → 记录
```

连续两次回滚 → 自动 FROZEN，转人工（`lab/state.py` 已支持，`lab run` 尚未自动触发，
属 Issue 0013 的一部分）。

## 5. 明确不做

- 全参数训练（预算不够、风险不可控）。
- 让主流程修改评测器或回滚逻辑（`SECURITY.md` 红线第 5 条）。
- 用未验证数据训练（会把自己产出的猜测当事实喂回去，这是最典型的自举污染）。
