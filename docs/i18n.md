## 为什么只翻译这五份

这五份是"决定别人要不要继续读"的那一层：**它是什么、怎么跑、怎么接自己的东西、AI 怎么执行**。
剩下的是参考材料——需要时再翻，避免 80% 的维护成本花在没人读的部分。

## 怎么加一门语言（3 步）

1. 复制 `README.en.md` 为 `README.<lang>.md`（`ja`、`ko`、`de`、`fr`、`es`、`ru`…）
2. **不要直译**：按目标语言的阅读习惯重写。保留全部数字与命令，因为它们要能被复算
3. 在本文的状态表里加一行，并在文件顶部加语言切换：

   ```markdown
   > [中文](README.md) | [English](README.en.md) | **日本語**
   ```

## 翻译时必须保留的东西（缺一不可）

| 必须保留 | 原因 |
|---|---|
| **所有数字**（−1.758、+1.597、5/5…） | 它们是可复算的；翻译不许"顺手改好看" |
| **所有命令**（`python -m lab.cli ...`） | 改一个字符就跑不了 |
| **局限声明**（"只在一个地图族上成立"） | 删掉就变成夸大 |
| **"不宣称意识"** | 这是承诺，不是修辞 |

## 允许改的东西

- 比喻和例子（中文的"8×8 房间"在英文里可以叫 "an 8×8 room"）
- 语序与句式（英文允许短句，中文常用长句）
- 语气（中文偏克制，英文可以更直接）

## 机器翻译的规则

如果要先出一版机器翻译占位：

1. 文件头必须写 `> Machine translation (unreviewed). Numbers and commands were copied verbatim.`
2. 数字与命令必须**逐字复制**，不许让翻译引擎碰
3. 标注为"待人工校对"，并在本文状态表里写 `🤖`

这样读者知道该信什么、不该信什么——跟这个项目的其他部分一个原则：**说清楚可靠性**。

## 一句提醒

新增语言时，别忘了 `docs/language.md` 的规则：**别把机制描述写成心理描述**。
英文里尤其容易写成 "the agent *wants* to avoid hazards"——那是错的，应为
"the policy's action distribution shifts away from hazards when the hurt penalty is negative"。
