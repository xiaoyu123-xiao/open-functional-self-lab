## 一、为什么"记了"还会犯

26 篇实验都记了，错照样犯——因为**记录不会拦人**。
记忆要有效，必须走完四步，缺一步就退化成"日记"：

```
实验结果 → 教训(结构化) → 强制检查(会拒绝) → 测试/脚本(每次必跑)
   ①            ②                ③                  ④
```

本仓库的对应物：

| 步 | 在哪 |
|---|---|
| ① 实验结果 | `docs/experiments/0001..0026`（每篇带复算命令） |
| ② 教训 | `lab/lessons.py` 的 `LESSONS`（9 条，只增不改） |
| ③ 强制检查 | `lab lessons --check` / `scripts/precheck_experiment.py` |
| ④ 每次必跑 | `scripts/preflight.py`（发布前 9 项里含它） |

## 二·五、探路与结论必须走两条通道（v0.40 补）

| 通道 | 允许 | 禁止 |
|---|---|---|
| 探路（`lab ref --explore`，任意样本） | 找方向、试想法 | 写进结论/总结表 |
| 结论（`lab ref --repeats ≥10`） | 写进实验记录与对外表述 | 少于 10 组、省掉区间 |

**这是我反复犯错的真正根因**：过去两种活动走同一条通道，4 组的跑和 25 组的跑写成同一种文档。
详见 [`BENCHMARK.md`](BENCHMARK.md)。

## 三、论文与自推怎么"合作"（不是二选一）

委托人指出我上一轮走到了另一个极端：开始只抄论文。正确做法是**固定分工**：

| 环节 | 谁负责 | 产出 |
|---|---|---|
| 找方向 | **文献**（`lab learn --online` + `knowledge`） | 候选方法、已知失败模式 |
| 定判据 | **自己**（先写判据再跑） | 可复算的验收条件 |
| 实现 | **自己**（按论文公式，不乱改） | 代码 + 单元测试 |
| 对照 | **自己**（本地消融：有它/没它） | 差值 + 区间 |
| 结论 | **两者交叉**：文献说法 vs 本地结果 | 一致就记下，冲突就写清 |

**如果文献结论与本地结果冲突，以本地为准，并记录冲突本身**——这是最有信息量的输出之一。

## 四、上下文丢失时的恢复顺序

如果你（或未来的我）打开这个仓库时什么都不记得，按这个顺序读：

1. `docs/MEMORY-PROTOCOL.md`（本文）——先知道规矩
2. `lab/lessons.py` 的 `LESSONS`——知道犯过什么错
3. `docs/EXPERIMENTS-SUMMARY.md`——知道哪些结论还站得住
4. `docs/AGENT-SELF-USE.md`——知道 AI 自己该怎么用这套东西
5. `python -m lab.cli lessons`——看每条教训的执行位置

**不要跳过第 2 步。** 跳过它，你就会重复"单次运行当结论""改奖励不改指标"这类错误。

## 五、每次开新实验前的三条命令

```bash
python -m lab.cli lessons                     # 我该注意什么
python scripts/precheck_experiment.py         # 教训库是否完整
python -m lab.cli lessons --check --repeats 12 --ci 0.2 0.9 --metric ate
```

第三条跑完，如果输出"凭据齐全"，才可以开始写结论。

## 六、这套东西怎么自我更新

- 新教训：在 `LESSONS` 里**新增**一条，并同时补一处执行位置（测试或脚本），
  否则 `precheck` 会失败——**没有执行位置的教训不算教训**。
- 旧教训被推翻：不要删，标 `superseded_by`，保留原编号（只增不改）。
