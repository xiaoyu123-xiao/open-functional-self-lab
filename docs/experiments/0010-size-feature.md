# 实验 0010：加上"地图尺寸"这一维之后，宽任务族又能迁移了

> 日期：2026-11-04　版本：v0.22.0
> 复算：`python -m lab.cli transfer --algo weighted --family wide --repeats 10`

---

## 背景

实验 0009 发现：把任务族从"只变危险区数量"扩到"再变地图尺寸"后，多任务的胜率从 5/5 掉到 3/5，
结论不成立。当时判断原因是**状态里没有"这是多大的一张图"**——同样的观测，在 8×8 和 12×12 上
对应的最优动作不同。

## 这次改了什么

只改一处：状态末尾加尺寸分档 `s0..s3`（≤8 / ≤10 / ≤12 / 更大），特征维度 21 → 25。
**没有改判据、没有换 seed、没有加训练量**（仍是 3 轮 × 40 回合）。

## 结果

| 指标 | 0009（无尺寸分档） | **0010（有尺寸分档）** |
|---|---|---|
| 重复次数 | 5 | 5 | 
| 配对胜率 | 60%（3/5） | **80%（4/5）** |
| — | — | **90%（9/10）** ← 加到 10 组后 |
| 单任务均分 | +0.413 | +0.362（±0.335） |
| 多任务均分 | +0.962 | +0.781（±0.421） |
| 配对差 | +0.549 | +0.419（±0.451） |

判据（胜率 ≥80% 且均值不下降）：**达成**。

## 怎么读这个结果（不高估）

1. **只加了一个特征就把胜率拉回来**，这再次说明：瓶颈在表示，不在训练量。
2. **配对差在缩小**（+0.549 → +0.419）：单任务的分数也降了，多任务降得更多。
   所以准确说法是"多任务在宽任务族上**稳定地略好于**单任务"，不是"明显更好"。
3. **90% 是 9/10**，仍有 1 次失败。换成 20 组可能变成 17/20 或 18/20——没测，不声称。
4. 波动仍然很大（±0.451），说明这个任务族本身不稳定。

## 三个版本连起来看

| 版本 | 状态里的任务信息 | 宽任务族胜率 |
|---|---|---|
| v0.16 | 只有危险区密度 | 60%（3/5） |
| v0.21 | 同上（先做宽任务族实验） | 60%（3/5） |
| **v0.22** | **+ 尺寸分档** | **90%（9/10）** |

**同一个结论出现第三次**：每次卡住都是"状态里少了一个维度"，加上去就好；
每次加上去都会让状态数变多，表格法会更难学——所以在 v0.22 里我换用的是线性/多臂策略，
没有回去用表格。

## 仍然不成立 / 没做

- 只测了尺寸 8/10/12，没有测 6 或 16
- 只测了一张地图族（同一套生成规则），换规则（比如迷宫式布局）没测
- 没有做显著性检验（10 组样本做 t 检验勉强，但我不打算用 p 值来撑结论）
