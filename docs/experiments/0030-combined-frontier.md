# 实验 0030：把三条路合成一条——结果取决于"受伤预算"

> 日期：2026-11-04　版本：v0.46.0
> 委托人指出：不该把"预算目标 / 换模型 / 改定位"拆成三条互斥的路，它们本可以合成一件事。
> 合成后的目标：**在受伤预算内尽量吃**。

---

## 一、先修两个真 bug（都影响历史结论）

| bug | 影响 |
|---|---|
| `_next_step` 的上下方向与 `env.moves` **相反** | 从 v0.27 起，"下一跳方向"特征一直是上下颠倒的——难怪它只带来微弱改善 |
| `train()` 漏传 3 个奖励参数（v0.41 已修） | 上一轮已处理 |

另外新增：`shield`（安全护栏）与 `avoid_hazards`（护栏模式下规划器把危险区当墙）。

## 二、五组策略的同一次测量（ref-1，6 个评测 seed，上限 30 份）

| 策略 | 吃到 | 受伤 |
|---|---|---|
| BFS / 规划器（危险区可走） | **30** | 15 |
| **规划器 + 护栏（绕开危险区）** | **13** | **0** |
| 学习器 | 10.2 | 7.8 |
| 学习器 + 护栏 | 4.0 | 0 |
| 学习器 + 护栏（笨回退） | 7.5 | 0 |

## 三、结论：不是"谁更强"，是"哪个预算下谁更强"

| 受伤预算 | 最优选择 | 吃到 |
|---|---|---|
| ≤ 15（宽松） | **BFS** | **30** |
| ≤ 7 | 学习器（10.2 / 7.8） | 10.2 |
| **≤ 0（零损伤）** | **规划器 + 护栏** | **13** |

**所以三条路的合成形态是"一条随预算移动的前沿"**，而不是三个并列选项：

- 要吃得最多 → BFS（代价：每回合撞 2.5 次）
- 要零损伤 → 规划器 + 护栏（代价：只吃 13/30）
- 中间地带 → 学习器

## 四、为什么"零损伤"吃不满

走廊里危险区密度高（6 个 + 稀疏隔断），把危险区当墙之后，**部分食物变得不可达**（或被墙+毒封住）。
所以 30 份 + 0 伤在这个世界**结构性不可达**——这不是方法问题，是地形问题。

## 五、可以发布的表述

> 在 ref-1 上，存在一条 (吃到, 受伤) 前沿：
> **BFS 占 (30, 15)，安全规划占 (13, 0)，线性学习器占 (10.2, 7.8)**。
> 三者在各自预算内互不支配；零损伤与满吃食无法同时达成。

这比"打不过 BFS"准确，也解释了十几次来回翻烧饼的原因：**它们比的不是同一个坐标轴**。
