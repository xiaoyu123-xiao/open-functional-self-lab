# 实验 0022：加受伤惩罚与规划特征的 2×2 对照——四条路都没赢过 BFS

> 日期：2026-11-04　版本：v0.34.0
> 复算：见文末脚本（16 个训练种子 × 两种训练预算 × 四种组合）

---

## 想解决什么

实验 0021 拆分数发现：加规划特征后**吃得多、伤得也多**，净值不升。
既然问题是"受伤太多"，那就**直接加大受伤惩罚**（−1 → −3），并做成 2×2 对照：

| 维度 | 取值 |
|---|---|
| 受伤惩罚 | −1（原） / −3（重罚） |
| 规划特征 | 关 / 开 |
| 训练预算 | 12×2（24 回合） / 30×3（90 回合） |

任务：10×10 走廊，危险区 6，非致命，120 步，16 个训练种子。

## 结果（全部负分，BFS 是 +1.63）

| 协议 | 受伤罚 | 特征 | 均分 | 吃到 | 受伤 | 差值 | 胜率 |
|---|---|---|---|---|---|---|---|
| 12×2 | −1 | 关 | −4.21 | 2.8 | 20.9 | +1.98 | 13/16 |
| 12×2 | −1 | 开 | −2.23 | 20.8 | 27.8 | | |
| 12×2 | −3 | 关 | −1.87 | **0.6** | 1.6 | −3.47 | 4/16 |
| 12×2 | −3 | 开 | −5.34 | 5.3 | 10.1 | | |
| 30×3 | −1 | 关 | −1.12 | 3.1 | 2.5 | −4.73 | 8/16 |
| 30×3 | −1 | 开 | −5.84 | 21.9 | 50.8 | | |
| 30×3 | −3 | 关 | −4.93 | 0.6 | 7.6 | −1.58 | 6/16 |
| 30×3 | −3 | 开 | −6.51 | 1.4 | 11.1 | | |

## 三条结论

1. **重罚把策略变成"蹲着不动"**：吃到从 2.8 掉到 **0.6 份**，受伤确实少了，但净分没救回来。
   这跟 v0.8 的护甲实验是同一个现象——**惩罚一重，最优解就是"别动"**。
2. **规划特征的效果稳定是"吃得多、伤得多"**：吃到 20.8 / 21.9 份，受伤也涨到 27.8 / 50.8。
   在"净值"这个指标上它不占优。
3. **四条路全部低于 BFS（+1.63）**。这不是参数没调好，是**方法在这一族任务上的上限**。

## 那这个特征还要不要

**要，但要按它的真实作用描述**：它是一个"**探索开关**"，不是"提分手段"。

| 用它 | 得到 | 代价 |
|---|---|---|
| 想让它多探索、多试路线 | 吃到份数 ×7 | 受伤上升，净分可能下降 |
| 想要高分 | ❌ 不适合 | 用 BFS 或改任务 |

用户提醒过"不要一棒子全部打死"——所以我不删它，而是**降级为可选项**（默认关闭，`--with-path` 才开）。

## 下一步（我认为该换方向了）

四条路都输给 BFS，说明**在"吃与伤"两难的任务上，一步前瞻 + 线性值函数已经到顶**。可选：

1. **改任务**：把"受伤"改成"受伤即结束"（致命），让净值只由"活多久 + 吃多少"决定
2. **改目标**：不优化净值，改成"最大化吃到份数，同时令受伤 ≤ 阈值"（约束优化）
3. **承认上限**：在本任务族上写"线性方法不如手写规则"，把精力转向别的任务族

我倾向第 1 条：它最可能让所有方法都转正，也最可能让差异重新变得可测。
