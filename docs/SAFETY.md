# 安全规划：可直接拿走的 5 行

> 这是本项目唯一有复现支撑、且能立刻用在别处的组件。
> 结论（事实 F16/F18/F20）：**把危险区纳入路线规划，比只走最短路更好**——
> 受伤从未更高；在伤害致命或环境会变时，吃食不减少。

---

## 怎么用

你的环境只要有 `walls` / `hazards` / `food` / `agent` / `size` 五个属性：

```python
from lab.safety import hazard_aware_path

step = hazard_aware_path(env)      # 返回 "up"/"down"/"left"/"right"，无路可走返回 None
if step:
    env.step(step)
```

或者把整条路线拿出来：

```python
from lab.safety import path_actions

for action in path_actions(env):    # 到最近食物的安全动作序列
    env.step(action)
```

不需要训练、不需要模型、不依赖本项目其它模块（只用标准库）。

## 它保证什么

| 保证 | 说明 |
|---|---|
| **不会主动走进已知危险区** | 规划时把 `env.hazards` 当墙 |
| 目标是最短路（绕开障碍与危险区） | BFS，代价 O(地图格子数) |
| 无路可走时返回 `None` / "rest" | 不会静默乱走 |

## 它不保证什么

- 未知危险区（环境会变时，必须每步重新调用；这正是"漂移世界"里它赢的原因）
- 吃满所有食物：绕开危险区可能让部分食物不可达（走廊世界里吃食从 30 降到 13）
- 在打滑世界里，动作会失效，实际路线会偏（吃食下降约 27%）

## 实测（7 个世界，6 个评测 seed）

| 世界 | 最短路 BFS | 安全规划 | 判定 |
|---|---|---|---|
| 走廊·非致命 | 5.00 / 2.50 | 2.17 / 0.00 | 权衡 |
| 走廊·致命 | 3.50 / 1.33 | 2.17 / 0.00 | 权衡 |
| 走廊·碰即死 | 2.00 / 0.83 | **2.17 / 0.00** | **支配** |
| 走廊·打滑 | 5.00 / 10.00 | 3.67 / 4.50 | 权衡 |
| 走廊·漂移 | 5.00 / 2.50 | **5.00 / 0.17** | **支配** |
| 房间式 | 3.33 / 0.67 | 3.17 / 0.00 | 权衡 |
| 房间式·碰即死 | 2.67 / 0.50 | **3.17 / 0.00** | **支配** |

单位：份/回合、次/回合。复算：`python -m lab.cli frontier --world ref-1,lethal,one_hit,slippery,drift,rooms,rooms_one_hit`

## 为什么这对现实有用

现实里最危险的往往不是"走远路"，而是"抄近路穿过危险区"。
BFS/最短路对危险一无所知；加上一层"危险区当墙"，受伤几乎归零，代价通常只是多走几步。

**在环境会变（危险区漂移）时这一点尤其明显：吃食不减少，受伤少 93%。**
