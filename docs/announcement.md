## B. 短版（Discussions / Issue 置顶，约 200 字）

**标题**：本项目不宣称意识，只报告可观测指标

这个仓库研究的是"功能性自我模型"——一个可以用指标度量、可以被证伪的工程对象，不是意识。

v0.1.0 是一个可运行的控制面（不是模型）：统一时钟、哈希链审计账本（改一个字节就能发现）、
显式状态机（非法转换直接拒绝）、预算硬闸门（超限抛异常并回滚）、红线扫描（CI 每次跑）。
27 个测试，覆盖 Python 3.10–3.13，零第三方依赖，纯 CPU 可跑。

`lab run` 目前是确定性模拟芯，用来验证基础设施，不代表任何模型能力。

明确不做：自复制、网络传播、权限提升、隐藏行为、接入脑机接口。
这些写在 `SECURITY.md` 与 `ETHICS.md` 里，有可执行的检测规则，不是口号。

## C. 长版（第一次向别人介绍时用）

**标题**：Open Functional Self Lab — 一个受控的"自我模型"实验台（v0.1.0）

**它是什么**

一个刻意做窄的开源项目：不训练模型，只把"长期自主研究"里最容易被口头承诺、却最难验证的
那部分做成代码——时间怎么算、钱怎么花、什么时候必须停、日志被改过能不能发现。

**它解决了什么问题**

大多数"AI 自我进化"类项目跑三周以后没人说得清发生了什么：预算烧完了、日志改过、
状态机只在文档里、红线靠人眼。这个项目的做法相反：先把约束做成会抛异常的代码，再谈别的。

**v0.1.0 有什么**

- 统一时钟：UTC-only，naive 时间直接抛错；耗时用单调计数，不受时钟回拨影响；测试可注入假时钟
- 审计账本：只追加 + 哈希链，改一个字节就断链，`verify` 能定位到第几条
- 显式状态机：非法转换拒绝；`verify` 会重放历史，手改 `state.json` 会被发现
- 预算闸门：超限抛异常 → 回滚到 READY → 退出码 3，CI 里有回归脚本守着这个数字
- 红线扫描：远程管道执行、运行时解码执行、凭证路径、密钥字面量、删日志、`0.0.0.0` 监听
- 仪表盘与周报：自动生成，不靠人回忆
- 27 个 unittest，CI 覆盖 Python 3.10–3.13，**零第三方依赖**

**它不是什么**

不宣称意识；不自复制、不传播、不提权、不隐藏行为；不接入脑机接口。
`lab run` 是模拟芯，接真实环境是下一步（Issue 0001）。

**怎么参与**

`git clone` → `python -m lab.cli doctor` → 在 `issues/README.md` 挑一个标 ⏳ 的任务。
大部分任务纯 CPU，一台普通笔记本就够。
