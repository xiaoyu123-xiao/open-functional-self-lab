# 指标口径

> 原则：**能被别人用你给的命令复现的，才叫指标。** 其余都是感想。

## 1. 现有指标（v0.1 可计算）

| 指标 | 定义 | 当前实现 | 备注 |
|---|---|---|---|
| `steps_executed` | 本轮成功落账的 step 事件数 | `lab run` → 账本 | 与 `--steps` 不等说明被预算截断 |
| `prediction_error` | 持久性基线（假设"下一步=上一步"）的四项平均绝对偏差：x/y/energy/damage | `lab/env.py::persistence_error` | 真正的对照基线，可直接被更强的预测器打败 |
| `rollback_count` | 历史中 `to == ROLLING_BACK` 的次数 | `lab viz` | 连续 2 次应触发冻结（Issue 0013） |
| `budget_used` | 账本 `budget` 事件按窗口求和 | `lab/budget.py` | 唯一权威来源 |
| `alert_unacked` | `alert` 事件数 − `ack` 事件数 | 仪表盘 | 长期 >0 说明告警失效 |
| `ledger_events` | 账本记录总数 | `lab verify` | 只增不减 |

## 2. 待定义（Issue 0003 之后）

- **行为连贯性**：同一情境下动作序列的重复率（基线是随机策略，必须给出对照）。
- **自我预测准确率**：预测"下一步观测 + 自身内部状态"的误差，与"朴素基线（上一步重复）"对比。
- **偏好稳定性**：相似情境下选择一致率。
- **未编程行为**：设计外的回避/探索模式占比。**这条最容易滑坡**——看到任何"意外行为"
  先排除实现 bug、随机种子、评估泄漏，再谈"涌现"。

## 3. 术语对照（写报告时强制）

| 不写 | 改写为 |
|---|---|
| 它产生了自我意识 | 在指标 X 上观察到 Y（样本 N，seed 列表），待独立复现 |
| 它想活下去 | 能量 < 阈值时，回避危险区动作占比从 A 升到 B（N=500） |
| 它有偏好 | 同一情境重复选择一致率 0.83 |
| 它学会了 | 任务通过率从 A 提升到 B，评测集版本 vX |

## 4. 结论的三档标注

所有结论必须标一个：

- `已验证`：≥2 个独立来源/独立复现，且命令可复现。
- `待验证`：只有一次运行，或只有单一来源。
- `证伪`：指标与假设相反。**这一档也要写进报告**，否则等于只记成功。

## 5. 无结论时的正确写法

```markdown
假设 H-007（能量低时回避危险区）在 500 步 × 3 seed 下：
avoid_ratio 基线 0.25，实验组 0.27，差值 95% CI 含 0。
结论：**证伪**（本样本量下无差异）。下一步：增大样本或改指标定义。
```

"没有差异"是完全合格的研究结果。把"没有差异"写成"初步显现趋势"，是这个领域最常见的
不诚实，也是本项目要在文档层直接堵住的。

## 6. 预测基线对比（`python -m lab.cli bench`）

三个预测器跑同一段环境（seed 1–3 × 200 步，共 600 步），实际结果：

| 预测器 | 平均误差 | 标准差 | 单步最优占比 |
|---|---|---|---|
| `random`（下界） | 1.6370 | 0.6688 | 0.0% |
| `persistence`（基线） | 0.0215 | 0.0695 | 72.5% |
| `linear`（速度外推） | 0.0210 | 0.0962 | 95.7% |

怎么读：

- `random` 明显更差 → 说明误差指标本身是有效的（否则三个都一样）。
- `linear` 平均只比基线好 **2.3%**，但标准差更大（0.0962 vs 0.0695）——它偶尔过冲。
  这点差距在 600 步上**不构成结论**，也不做显著性检验（样本小，极易虚假显著）。
- 想要更大的差距，得换更复杂的任务（Issue 0008），不是调参。

完整报告由命令自动写到 `state/reports/bench-YYYY-MM-DD.md`，同时向账本追加一条 `bench` 事件。
