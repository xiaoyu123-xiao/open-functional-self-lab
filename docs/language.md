# 语言纪律：哪些词不许用，为什么

> 这份文件是因为一次真实批评才存在的：我写了"它怕死""它宁可少活也不肯挂彩"，
> 于是读的人以为"它有人的想法"。**那是我的用词造成的，不是系统的属性。**

## 三条硬规则

1. **不写心理动词**：想、怕、喜欢、讨厌、觉得、意识到、渴望、宁愿。
   系统里没有这些变量。写了就是给读者塞一个不存在的机制。
2. **"选择"要加限定**：不写"它选择躲开"，写"在该奖励函数下，避开危险区的期望收益更高"。
3. **每个行为描述必须能落到一个可测量上**：指标名 + 样本量 + 变化量。

## 对照表

| 不许写 | 改写为 |
|---|---|
| 它怕死 | 受伤 −1、死亡 −5 的定价下，"不受伤"是该奖励的近似最优解 |
| 它宁可少吃也不受伤 | 遇到危险区时绕行率 100%，代价是每局少吃 19 份食物 |
| 它胆小 / 变保守了 | 危险区进入率从 0.051 降到 0.000；食物获取从 100 降到 75 |
| 它想活下去 | 能量低于阈值时，回避危险区的动作占比上升（N=500） |
| 它学会了害怕 | 受伤后进入危险区的概率下降 X%（对比训练前，N=…） |
| 它有意识了 | （不许写。最多写"某项代理指标上升"，并注明不能证明意识） |

## 允许使用这些词的两种情况

1. **引用别人的话**（用引号包起来，并注明"这是原话"）。
2. **明确否定**（"它不是怕死，而是……"）——但更好的写法是直接说机制，不要先立个稻草人。

## 自查方法

```bash
python scripts/check_language.py          # 扫全仓库，列出可疑用法
```

脚本的启发式：命中禁用词、且该行**不含**引号/否定词/对照表标记时，才报。
它不完美，但能把"我又写了拟人化描述"这件事从"没人发现"变成"构建时就提示"。

## 为什么值得较真

因为这个项目最容易被误读的地方，不是技术，是**读者把工程描述当成了心理描述**。
一句"它怕死"能让整个项目被理解成"他们在做有意识的 AI"，
而实际做的是"奖励函数下的策略优化"。**措辞不是修辞问题，是准确性问题。**
