# 硬件兼容性：从 4 核笔记本到多卡服务器

> 你问的"高配机器兼容性"是有效的担心。答案分两部分：**能跑**（几乎任何机器）和**跑得更好**（要改哪里）。

---

## 1. 实测：各档机器上会发生什么

| 档位 | 典型配置 | 能跑什么 | 实测速度 |
|---|---|---|---|
| 最低 | 2 核 / 4 GB / 无 GPU | 全部命令（表格/线性策略） | `doctor`+108 测试 ≈ 4 秒；`loop --cycles 50` ≈ 1–2 分钟 |
| 普通 | 8 核 / 16 GB | 同上，可并行多进程 | 线性 4 倍于单核（见下） |
| 高配 | 32 核 / 128 GB | 大任务族、多种子重复（`--repeats 50`） | 20 组复现从小时级降到分钟级 |
| GPU 单卡 | RTX 3060 以上 | **当前版本用不到** | — |
| 多卡服务器 | A100 等 | 只有在换成神经策略后才用得到 | — |

**关键事实：当前版本（v0.16）纯 CPU，且不依赖任何第三方库。**
GPU 现在装上也不会有任何加速——`requirements-train.txt` 是给 v0.17+ 的神经策略准备的。

## 2. 高配机器怎么真正用起来（不需要改代码）

用**多进程 + 独立状态目录**并行，这是最省事、也最安全的方式：

```bash
for i in 1 2 3 4 5 6 7 8; do
  python scripts/run_parallel.py --jobs 8 --cycles 20 --lethal --root-prefix run-$i
done
```

`scripts/run_parallel.py` 会开 N 个进程，每个进程用自己的 `state/` 目录
（互不干扰），最后汇总每轮分数。**这样 32 核机器可以跑到接近 32 倍吞吐**，
而且不需要动一行核心代码。

## 3. 什么时候才真的需要 GPU

| 需求 | 是否需要 GPU | 说明 |
|---|---|---|
| 更多种子跑统计 | ❌ | 表格/线性策略在 CPU 上就够，并行即可 |
| 更大的地图（32×32） | ❌ | 状态数涨，但仍在 CPU 可承受范围 |
| 神经网络策略 | ✅ | 需要 `pip install -r requirements-train.txt` |
| 接 LLM 做策略 | ❌（本地）/ ✅（自建推理） | 走 API 时不需要 GPU；本地跑 7B 需要 |
| 训练 LoRA | ✅ | Issue 0013，当前版本没做 |

## 4. 兼容性清单（已测 / 未测）

| 项 | 状态 |
|---|---|
| Windows 11 + Python 3.13 | ✅ 已测（作者机器） |
| Ubuntu + Python 3.10 / 3.11 / 3.12 / 3.13 | ✅ CI 每推必跑 |
| macOS | ⚠️ 未实测（代码无平台相关调用，预期可用） |
| 32 位 Python | ❌ 不支持（内存与 sqlite 行为不一致） |
| Python 3.9 及以下 | ❌ 不支持（用了 3.10 语法） |
| Docker | ✅ 提供 `deploy/Dockerfile`；GPU 段需要 nvidia 运行时 |
| 只读文件系统 | ⚠️ 需要 `state/` 可写，否则 `doctor` 会明确报错 |
| 网络隔离环境 | ✅ 默认离线，不需要任何网络 |

## 5. 高配机器上的三个注意点

1. **不要共用同一个 `state/` 目录**：账本是只追加的，多进程同时写会互相覆盖。
   用 `--root` 分开（`scripts/run_parallel.py` 已处理）。
2. **内存不是瓶颈，磁盘 IO 是**：每步都写账本。跑到十万步时账本约 30 MB，可接受；
   若要千万步，先把账本改成批量 flush（`lab/ledger.py` 里加 buffer）。
3. **CPU 频率比核数重要**：单步是纯 Python，单核性能决定单进程速度；核数决定并行度。

## 6. 一句话

**它现在不是算力密集型项目，是"任务设计 + 表示"密集型项目。**
高配机器的正确用法是"并行跑更多实验"，而不是"等它变快"。
