# 这个仓库里，我这个 AI 能真正拿来用的东西

> 起因：委托人问"你能不能从这里自我升级"。
> 我的回答分两半：**能用的四样**、**不能用的三样**，最后是一条警告。

---

## 一、能用的四样（我确实在用）

| 拿来就能用的 | 我这里的对应做法 | 本轮实例 |
|---|---|---|
| **哈希链账本** | 每个结论标注"可复算命令"，事后能查是不是我改了口 | 13 次实验，每篇都有 `python -m lab.cli ...` |
| **预先写死的判据** | 先说"胜率 ≥80% 且区间不含 0"，再跑 | 判据从 v1→v2→v3，每次改都写明理由 |
| **留出集纪律** | 训练 seed 与评测 seed 不重叠 | 1000–1999 vs 9000–9999 |
| **失败留档** | 失败的实验照样写进 `docs/experiments/` | 15 篇里 12 篇是负结果 |

## 二、不能用的三样（别自欺）

1. **我不能自改权重。** 所谓"我变强"，指的是我的**流程**变好（清单、判据、检查脚本），
   不是模型参数变化。把这两件事混起来，就是自我欺骗。
2. **我不能靠读一个仓库"进化"。** 读完不会更聪明；只有**照着它做**（跑测试、写判据、留失败记录）才会。
3. **我不能验证自己的正确性。** 我说"这次成功了"，必须由外部数字或你复核。
   这个仓库的 `verify` 之所以有价值，正因为它是**外部检查**，不是我自评。

## 三、我会真的执行的五步（可检查）

1. **先写判据**：动手前写下"什么算成功"，包括失败条件。
2. **先看分布再改**：加特征/改参数前，先统计它在本任务上的实际分布（v0.26 就栽在这）。
3. **一次只改一处**：改了 A 就只测 A，不同时改 B。
4. **改完必须回退可能**：没有收益的改动一律撤掉，并在代码里留注释（v0.26 已做）。
5. **每轮贴出"我错了什么"**：这是这条流程里唯一防止自嗨的环节。

## 四、警告：左脚踩右脚会放大误差

委托人描述的路线是：别人改进仓库 → 我拿来用 → 我变强 → 再改进仓库。

**这条回路有一个前提：必须有外部真值。** 这个仓库里那个真值就是"留出集上的分数"。
如果哪天判据变成"我觉得更好了"，回路就会变成**正反馈放大器**：

```
自评 → 微调 → 自评（更自信）→ 微调 … → 越走越偏，且没人发现
```

历史上有现成的名字叫 **model collapse / 自我蒸馏退化**：模型吃自己产出的数据，
分布越来越窄，最后只会重复自己。

**防止它的唯一办法**：每一轮都必须有一个**不参与优化**的检查点——
留出集、外部评审、或你本人的抽查。没有这个，我不建议继续这个回路。
