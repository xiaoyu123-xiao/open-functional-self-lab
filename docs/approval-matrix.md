# 审批矩阵

> 规则：表格里没写的事，默认**不准做**；要做先补一行，再走流程。
> "批准人"指 GitHub 上的 approve，不是口头同意。

| 动作 | 批准人 | 人数 | 附加要求 | 落点 |
|---|---|---|---|---|
| 普通 PR（文档/测试/新模块） | 维护者 | 1 | CI 绿 | — |
| 新增白名单域名 | 维护者 | 1 | 写清条款与速率，季度复审 | `search/README.md` |
| 移除白名单域名 | 维护者 | 1 | 记录原因 | 同上 |
| 调整预算上限（任一类别） | 发起人 + 维护者 | 2 | PR 描述写明理由与新上限 | `lab.config.json` |
| 修改红线规则 | 维护者 ≥2 + 发起人 | 3 | 公开讨论 ≥7 天 + 回滚演练 | `lab/policy.py` |
| 修改预算闸门逻辑 | 维护者 ≥2 + 发起人 | 3 | 必须有回归脚本通过 | `lab/budget.py` |
| 修改账本哈希算法 | 维护者 ≥2 + 发起人 | 3 | 需迁移方案（旧账本如何处理） | `lab/ledger.py` |
| 修改 `SECURITY.md` | 维护者 ≥2 + 发起人 | 3 | 公开讨论 ≥7 天 | `SECURITY.md` |
| 合并参数更新（LoRA） | 维护者 | 2 | eval-gate 全过 + 有 checkpoint | `evolve/README.md` |
| 触发回滚 | 任一维护者 | 1 | 自动触发也需事后复核 | `lab/cli.py` |
| 解除冻结（unfreeze） | 维护者 | 1 | 必须 `--by <名字>`，写进账本 | 同上 |
| 发布新版本 / 打 tag | 维护者 | 1 | CHANGELOG + CITATION 日期对齐 | `docs/publish.md` |
| 归档项目 | 发起人 | 1 | 说明数据去向与接手人 | `GOVERNANCE.md` |
| 接入真实模型 | 维护者 | 2 | 预算 + 沙箱 + 回滚点 | Issue 0003 |
| 任何联网行为 | 维护者 | 1 | 先落白名单，再从 `profiles: online` 启动 | `space/README.md` |

## 不存在的审批

- ❌ "发起人一个人说了算"：`GOVERNANCE.md` 要求维护者 ≥2，单人项目自动 FROZEN。
- ❌ "先合并，回头补测试"：CI 红就是红，没有 no-verify。
- ❌ "口头批准"：所有批准必须是 PR approve 或在 Issue 里明确回复，可被检索。
