# 把它接到模型上会是什么样

> 现在这个仓库**不含任何大模型**。它是一套"外骨骼"：账本、预算、状态机、评测、权限。
> 这份文档说明：如果你想接一个模型进来，它会变成什么、以及要改哪一处。

---

## 1. 先说结论：接模型不会改变记账逻辑

```
┌─────────────── 不变的部分（v0.16 已有）───────────────┐
│ 时钟 · 哈希链账本 · 状态机 · 预算闸门 · 权限 · 评测   │
└───────────────────────────┬───────────────────────────┘
                            │  只替换这里
              ┌─────────────▼─────────────┐
              │  策略（谁来"决定动作"）    │
              │  现在：Q-learning / BFS    │
              │  以后：LLM / 微调模型      │
              └───────────────────────────┘
```

接模型 = 换掉 `lab/agent.py` 里"选动作"的那一层，**其余一行都不用改**。
账本、预算、回滚、越权检查照旧生效——这正是这套外骨骼的价值。

## 2. 三种接法（按侵入性从低到高）

| 接法 | 模型做什么 | 改哪里 | 适合 |
|---|---|---|---|
| **A. 提议者** | 只负责"提下一步做什么"，不直接执行 | `lab/collaborate` 的提案来源 | 最安全，先跑起来 |
| **B. 策略** | 直接输出动作/实验参数 | 新增 `lab/backends/llm.py`，实现 `act(state)` | 想让模型真的驱动行为 |
| **C. 评审者** | 只判断"这一轮通过/不通过" | `lab review` 的判定逻辑 | 想让评审独立于执行者 |

**推荐顺序：A → C → B。** 因为 A、C 出错只是"建议不好"，B 出错会直接烧预算。

## 3. 接法 B 的最小实现（伪代码，约 30 行）

```python
class LLMPolicy:
    def __init__(self, client, model="...", budget=None):
        self.client = client          # 任何 OpenAI 兼容接口
        self.model = model
        self.budget = budget          # 复用 lab/budget.py

    def act(self, state: str) -> str:
        self.budget.charge("llm_calls_per_day", 1)     # 先付钱，再调用
        prompt = f"当前状态：{state}\n可选动作：up/down/left/right/rest\n只回一个词。"
        reply = self.client.chat(prompt, model=self.model, max_tokens=4)
        action = reply.strip().lower()
        if action not in {"up", "down", "left", "right", "rest"}:
            return "rest"            # 非法输出一律降级为"不动"，不要猜
        return action
```

关键点（都是踩过的坑）：

1. **先扣预算再调用**，否则一次失控调用就能把额度烧穿。
2. **非法输出降级**，不要试图解析/纠正模型的自由文本。
3. **把 prompt 与回复都记进账本**（`event="llm_call"`），否则事后无法复现。

## 4. 接进 `lab run` 的改动量

| 文件 | 改动 |
|---|---|
| `lab/agent.py` | 加一个 `protocol`：任何有 `act(state)` 的对象都能当策略 |
| `lab/cli.py` | `--policy llm` 时构造 `LLMPolicy` |
| `lab/config.json` | 新增 `llm_calls_per_day` 预算项 |
| `lab/policy.py` | 新增红线：prompt 里不许出现凭证、不许让模型"输出并执行命令" |
| `docs/metrics.md` | 新增：模型动作合法率、每轮成本、延迟 |

## 5. 模型进来之后，会变成什么样（诚实预期）

| 可能 | 说明 |
|---|---|
| 动作合法率会先掉 | LLM 经常输出"向左走三步"这种不能执行的文本；要先做 5 选 1 约束 |
| 分数不一定更高 | 这个任务是"最短路径 + 避危险"，表格法已经很强；LLM 的优势在**换任务族**时 |
| 成本会变成主要约束 | 一次 60 步的回合 = 60 次调用；按 0.001 元/次算，一轮 3 毛 |
| 审计价值更大 | 每步都有 prompt/回复记录，"为什么它这么走"第一次可查 |

## 6. 如果你有很强的机器（多卡/大内存）

这个仓库现在的瓶颈**不在算力，在任务设计**。加显卡不会让 +1.60 变成 +5。
真正能吃算力的三件事（按性价比排）：

1. **并行采样**：多个 `--root` 目录同时跑（见 `docs/HARDWARE.md`）
2. **更大的环境**：把 8×8 改成 32×32、加动态障碍（改 `lab/env.py` 的 `SIZE` 与生成逻辑）
3. **神经网络策略**：需要 `requirements-train.txt` 里的 torch，且只在任务变复杂后才有意义

**别为了"用上 GPU"而加复杂度**——那是本项目最反感的做法。
