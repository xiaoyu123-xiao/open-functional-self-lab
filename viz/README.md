# 可视化

> 实现：`lab/viz.py`（仪表盘）、`lab/report.py`（周报）
> 生成物：`viz/status.md`、`state/reports/weekly-YYYY-MM-DD.md`

第 #52 轮你说："光生成一串东西，本人看不懂，也不知道该如何继续往下执行。"
所以这里的原则是：**仪表盘是给人做决定用的，不是给机器存档用的。**

## 1. 仪表盘（`viz/status.md`）

每次 `python -m lab.cli viz` 覆盖生成，包含四块：

| 区块 | 回答的问题 |
|---|---|
| 概览 | 现在什么状态？跑了多少步？回滚几次？有几条告警没回？ |
| 预算 | 还剩多少额度？哪一类快用完了？ |
| 最近事件 | 刚才到底发生了什么？（最近 8 条，带 seq 和时间） |
| 状态机图 | 我现在能往哪走？（Mermaid，标注当前状态） |

## 2. 周报（`python -m lab.cli report`）

固定五段：本周进展 / 预算消耗 / 事件分布 / 风险与待办 / **写下你的部分**。

最后一段是刻意留空的：模板不能替人写"我学到了什么"。留空位置比自动摘要更有用，
因为它强迫每周至少写一句。

## 3. 图表规范

- 状态机：`stateDiagram-v2`，由 `lab/state.py` 的转换表自动生成，**不手写**。
  手写的图三个月后一定和代码不一致。
- 依赖图 / 数据流：`logic/README.md`、`space/README.md` 里手绘（更新频率低，值得手写）。
- 所有图表用 Mermaid，不用图片。理由：能 diff、能在 GitHub 直接渲染、不需要图床。

## 4. 还没有的（不承诺）

- Grafana / Streamlit 实时面板：**不做**。单人项目上实时面板，最后只是多一个要维护的服务。
- 告警推送（webhook / 邮件）：属 Issue 0019，前提是先把"分级 + 去重 + 回应率"跑顺。
- 模型内部指标可视化：接入真实模型（Issue 0003）之后才有意义。

## 5. 验收标准（Issue 0017 已实现部分）

- `viz` 生成的文件里必须出现：当前状态、预算余量、最近事件、Mermaid 图。
- 生成过程不联网、不读 `.env`、不渲染外部图片。
- 同一状态 + 同一 `--fake-now` 下，生成结果逐字节相同（可 diff）。
