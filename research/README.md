# 研究循环

> 状态：规范已定，实现属 Issue 0003 / 0007 / 0008 / 0012。
> 这一段是把对话里"找资料→提假设→做实验→自我更新"翻译成可验收步骤的地方。

## 1. 七步闭环（每步都有失败出口）

| 步 | 做什么 | 产出 | 失败出口 |
|---|---|---|---|
| 1 | 检索 | 候选文献清单（只存引用+摘要） | 预算耗尽 → 停止并记录 |
| 2 | 提假设 | 每条含：主张、可测指标、证伪条件、资源、回滚点 | 无法证伪 → 退化想法，不入库 |
| 3 | 设计实验 | 变量、对照、样本量、停止条件 | 无对照 → 不许跑 |
| 4 | 执行 | `lab run` + 账本 | 超预算 → 回滚（退出码 3） |
| 5 | 独立验证 | 通过/不通过/存疑 + 理由 | 验证器与执行者同源 → 结果作废 |
| 6 | 记录 | 成功/失败都入账本 | 只记成功 → PR 会被拒 |
| 7 | 课程生成 | 下一轮更难的任务 | 无新任务 → 项目进 REVIEWING |

## 2. 假设的写法（唯一被接受的格式）

```yaml
claim: 在能量低于 0.3 时，回避危险区的动作占比高于随机基线
metric: avoid_ratio（定义见 docs/metrics.md）
falsify: 若 avoid_ratio 与随机基线的差值 95% 置信区间包含 0，则证伪
sample: 500 步 × 3 个 seed
resource: CPU 2h, API 0
rollback: 删除该假设的 run 记录，保留失败日志
```

没有 `falsify` 字段的假设一律不收。这条规则直接来自对话里最容易滑坡的地方：
"它是不是更懂自己了"——不可证伪，所以不是假设，是感想。

## 3. 知识入库规则（Issue 0012）

- **已验证**：≥2 个独立来源（不同作者、不同机构、互不引用）支持同一主张。
- **待验证**：只有 1 个来源。
- **争议**：来源间明确矛盾，保留双方证据，不选边。
- **过期**：超过 TTL，降级为待验证，需重新确认。
- 同一来源的多个副本**不算**独立来源。

## 4. 多学科任务卡

| 域 | 最小任务 | 判据 |
|---|---|---|
| 数学 | 给定小规模命题，枚举反例 | 反例可机器验证；禁止宣称解决开放问题 |
| 语文 | 长文前后矛盾检测 | 标注冲突句对；人工抽检一致率 |
| 外语 | 中英对照找信息差 + 回译 | 回译相似度 + 术语准确率 |
| 材料 | 公开数据库检索 + 基线对比 | 预测误差；禁止大规模 DFT |

## 5. 验证器独立性（Issue 0005）

- 不得与执行者是同一模型/同一份代码。
- 只能回答"过/不过/存疑"并附理由，不给分数（分数会被优化）。
- 版本与评测集版本必须记进账本。
- 定期人工抽检：随机 5% 的判定由人复核，一致率 <90% 就说明验证器漂移了。

## 6. 与"自我进化"的距离

这套循环能让**知识库**变好（更多已验证条目）、让**流程**变稳（更少回滚）。
它不会让系统"想变得更聪明"——那需要一个内在目标，而内在目标是本项目的**禁区**：
一旦有内在目标，预算闸门就会被当成障碍去绕过。这正是不做的理由，不是能力不足。
